# 合同管理系统 - 需求分析报告

## 一、引言

### 1.1 编写目的

本文档对"合同管理系统"进行详细的需求分析，明确系统的功能需求、非功能需求和约束条件，为后续的系统设计和开发提供依据。

### 1.2 项目背景

企业日常运营中涉及大量合同管理工作，包括合同的起草、多部门会签、管理层审批、正式签订等环节。传统的手工管理模式存在效率低下、流程不透明、难以追溯等问题。本系统旨在利用信息技术手段，基于B/S架构实现合同管理的规范化、流程化和信息化，同时引入AI智能起草、电子签名、邮件通知等现代化功能，提升合同管理效率。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| 合同 | 企业与外部单位签署的具有法律效力的文件 |
| 会签 | 合同在定稿前由相关部门/人员共同审阅并签署意见的过程 |
| 定稿 | 根据会签意见修改后确定的最终合同文本 |
| RBAC | Role-Based Access Control，基于角色的访问控制 |
| 流程 | 合同从创建到归档所经历的状态变化序列 |
| B/S架构 | Browser/Server架构，浏览器/服务器模式 |
| 电子签名 | 使用Canvas手写方式在合同上签署的数字化签名 |
| AI智能起草 | 基于本地AI模型自动生成合同内容的功能 |

## 三、功能需求详述

### 3.1 用户管理模块

#### 3.1.1 用户注册

| 属性 | 说明 |
|------|------|
| **功能描述** | 新用户通过Web注册页面创建账号 |
| **前置条件** | 系统已启动，浏览器可访问 http://localhost:8080 |
| **输入** | 用户名（唯一）、密码（两次确认） |
| **输出** | 注册成功提示（提示等待审核）/ 失败原因 |
| **业务规则** | 用户名不能重复；密码不能为空；注册后状态为"待审核"，需管理员审核后才可登录 |
| **异常处理** | 用户名已存在时提示更换；两次密码不一致时提示重新输入 |

#### 3.1.2 用户登录

| 属性 | 说明 |
|------|------|
| **功能描述** | 已审核通过的用户通过Web登录页面登录系统 |
| **前置条件** | 用户账号存在且状态为"已通过" |
| **输入** | 用户名、密码 |
| **输出** | 登录成功进入主页面 / 登录失败提示具体原因 |
| **业务规则** | 区分三种失败场景：①用户不存在或密码错误 ②账号待审核中 ③账号被管理员拒绝 |

#### 3.1.3 用户审核（管理员）

| 属性 | 说明 |
|------|------|
| **功能描述** | 管理员对待审核用户进行通过/拒绝操作 |
| **前置条件** | 当前用户为管理员身份 |
| **操作** | 在待审核列表中选择用户，点击"通过"或"拒绝" |
| **业务规则** | 通过后用户可正常登录；拒绝后用户无法登录；操作记入日志 |

#### 3.1.4 安全约束

- **自保护机制**：管理员不能取消自己的管理员角色，防止误操作导致无管理员
- **admin账户保护**：内置管理员账户不可删除
- **后端API验证**：Controller层对每个API请求验证用户权限

### 3.2 合同管理模块

#### 3.2.1 起草合同 (F01)

| 属性 | 说明 |
|------|------|
| **功能描述** | 有起草权限的用户创建新的合同 |
| **输入字段** | 合同名称（必填）、客户（必选）、开始时间、结束时间、合同内容（必填） |
| **默认值** | 开始时间=当天日期；结束时间=1年后 |
| **时间校验** | 结束时间必须晚于开始时间至少1天；自动修正 |
| **输出** | 起草成功后生成合同编号（格式：HT+YYYYMMDD+序号），合同状态设为"起草" |
| **防重复提交** | 提交按钮点击后锁定，防止重复提交 |

#### 3.2.2 分配合同 (F06)

| 属性 | 说明 |
|------|------|
| **功能描述** | 管理员为已起草的合同指定各环节负责人 |
| **前置条件** | 存在状态为"起草"的合同 |
| **分配项** | 会签人员（多人）、审批人员（多人）、签订人员（多人） |
| **权限过滤** | 会签列表只显示有F02权限的用户；审批列表只显示有F04权限的用户；签订列表只显示有F05权限的用户 |
| **业务规则** | 三组人员必须全部指定才能提交分配 |
| **邮件通知** | 分配完成后自动发送邮件通知相关人员 |

#### 3.2.3 会签合同 (F02)

| 属性 | 说明 |
|------|------|
| **功能描述** | 被指定的会签人员对合同进行审阅并填写意见 |
| **前置条件** | 当前用户在合同的会签人员列表中，且合同处于"已分配-待会签"状态 |
| **操作** | 查看合同内容 → 查看历史意见 → 填写会签意见 → 确认提交 |
| **业务规则** | 所有人签完成后合同进入"待定稿"状态 |

#### 3.2.4 定稿合同 (F03)

| 属性 | 说明 |
|------|------|
| **功能描述** | 起草人根据会签意见确定最终合同文本 |
| **前置条件** | 所有会签人员均已完成会签 |
| **历史意见** | 可查看所有会签人员的意见，以及审批否决的意见（如有） |
| **输出** | 定稿后的合同进入"待审批"状态 |

#### 3.2.5 审批合同 (F04)

| 属性 | 说明 |
|------|------|
| **功能描述** | 审批人对定稿后的合同进行批准或否决 |
| **前置条件** | 当前用户在合同的审批人员列表中 |
| **操作** | 选择"通过"或"否决"并可填写审批意见 |
| **业务规则** | 任一人否决则合同退回定稿阶段（非终止）；所有人通过后进入"待签订"状态 |
| **否决退回** | 审批否决后合同退回定稿阶段，否决意见保留供起草人查看，起草人可修改后重新定稿 |
| **邮件通知** | 否决时自动邮件通知起草人 |

#### 3.2.6 签订合同 (F05)

| 属性 | 说明 |
|------|------|
| **功能描述** | 签订人完成合同的正式签订 |
| **前置条件** | 合同已通过审批 |
| **电子签名** | 使用Canvas手写签名，签名以图片形式插入合同 |
| **输出** | 合同状态变为"签订完成" |

                                               ↑             │
                                               └── 否决退回 ←┘

### 3.4 智能辅助模块

#### 3.4.1 AI智能起草

| 属性 | 说明 |
|------|------|
| **功能描述** | 基于Ollama本地AI模型自动生成合同内容 |
| **AI模型** | qwen2:7b，通过Ollama本地部署（端口11434） |
| **工作模式** | 模板填充模式，根据合同名称和客户信息生成合同正文 |
| **可编辑性** | AI生成的内容可手动修改调整 |
| **容错处理** | AI服务不可用时给出友好提示，不影响手动起草 |

#### 3.4.2 电子签名

| 属性 | 说明 |
|------|------|
| **功能描述** | 签订合同时使用Canvas手写签名 |
| **实现方式** | HTML5 Canvas + JavaScript鼠标/触摸事件 |
| **签名输出** | PNG图片格式，保存到数据库 |
| **操作** | 手写签名、清除重写、确认提交 |
| **配置** | 画布尺寸、笔触颜色可在系统设置中配置 |

#### 3.4.3 邮件通知

| 属性 | 说明 |
|------|------|
| **功能描述** | 合同流程关键节点自动发送邮件通知 |
| **通知场景** | 合同分配、会签完成、审批通过、审批否决 |
| **通知对象** | 相关的会签/审批/签订人员或起草人 |
| **配置** | SMTP服务器、端口、邮箱、密码等在系统设置中配置 |
| **容错** | 邮件发送失败不影响主流程 |

#### 3.4.4 合同导出

| 属性 | 说明 |
|------|------|
| **功能描述** | 将合同导出为PDF或DOCX文件 |
| **技术实现** | iText生成PDF |

## 四、非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 页面响应时间 | < 2秒（本地数据库环境下） |
| 并发用户数 | 支持多用户同时访问（Spring Boot内嵌Tomcat） |
| 数据量支撑 | 支持万级合同记录查询 |

### 4.2 安全需求

| 需求项 | 实现方式 |
|--------|----------|
| 身份认证 | 用户名+密码登录验证 |
| 授权控制 | RBAC角色权限，每个功能点独立控制，后端API验证 |
| 操作审计 | 关键操作自动记录日志 |
| 自保护 | 管理员不能取消自身管理员权限 |
| 防重复提交 | 按钮锁定机制 |

### 4.3 易用性需求

| 需求项 | 实现方式 |
|--------|----------|
| 浏览器访问 | 无需安装客户端，通过浏览器即可使用 |
| 友好提示 | 区分不同错误原因给出精准提示 |
| 智能辅助 | AI智能起草、日期自动校验、待办任务提醒 |
| 响应式布局 | Bootstrap栅格系统，适配不同屏幕尺寸 |

### 4.4 可维护性需求

| 需求项 | 实现方式 |
|--------|----------|
| 分层架构 | Controller-Service-DAO三层分离 |
| 配置外部化 | application.properties + t_settings表 |
| 自动初始化 | Spring Boot启动时自动检测和初始化数据库 |
