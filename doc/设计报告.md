# 合同管理系统 - 设计报告

## 一、系统总体设计

### 1.1 设计原则

| 原则 | 说明 |
|------|------|
| **分层解耦** | View → Service → DAO 三层分离，降低耦合度 |
| **单一职责** | 每个类只负责一个领域的业务逻辑 |
| **开闭原则** | 通过RBAC权限配置而非硬编码来控制功能可见性 |
| **最小知识** | 层间只通过实体对象传递数据 |

## 四、核心模块设计

### 4.1 启动流程设计

```
运行 App.main()
    │
    ├─ 1. 显示启动画面(SplashScreen) + 进度条
    │
    ├─ 2. tryConnect(): 尝试连接数据库
    │      ├─ 成功 → 继续
    │      └─ 失败 → 弹窗询问是否启动数据库
    │           ├─ 是 → Runtime.exec("start.bat") → 每5秒轮询tryConnect()
    │           │        ├─ 成功 → 继续
    │           │        └─ 超时(5分钟) → 报错退出
    │           └─ 否 → 退出程序
    │
    ├─ 3. checkTablesExist(): 检查表是否存在
    │      ├─ 存在 → 继续
    │      └─ 不存在 → initDatabase(): 执行init.sql建表+插数据
    │
    ├─ 4. migrateDatabase(): 兼容性迁移
    │      └─ 检测t_user是否有status列，没有则ALTER TABLE添加
    │
    └─ 5. 显示 LoginFrame 登录界面
```

### 4.2 权限控制设计（RBAC模型）

```
User ──(N:M)── Right ──(N:1)── Role ──(N:M)── Function
 (用户)          (权限表)      (角色)           (功能)

权限判断流程：
1. 用户登录 → 查询t_right获取用户的所有角色
2. 遍历每个角色 → 从t_role.functions解析功能编号列表
3. 合并为Set<String> userFunctions
4. MainFrame创建导航时 → if(userFunctions.contains("F01")) 显示"起草合同"
5. 各Panel初始化时 → 同样通过userFunctions控制功能可见性
```

### 4.4 日期智能校验设计

```
用户操作触发校验的时机：
┌─────────────────────────────────────────────────────┐
│                                                     │
│  txtBeginTime 失焦                                   │
│       ↓                                             │
│  validateAndFixEndTime()                             │
│       ↓                                             │
│  解析开始时间和结束时间                                │
│       ↓                                             │
│  if (结束 ≤ 开始):                                   │
│       结束 = 开始 + 1天  (自动修正)                   │
│                                                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  txtEndTime 失焦                                     │
│       ↓                                             │
│  validateAndFixEndTime()  (同上逻辑)                  │
│                                                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  点击 [-半年]/[-一年]/[+半年]/[+一年] 按钮            │
│       ↓                                             │
│  adjustEndTime(months)                               │
│       ↓                                             │
│  计算 minDate = 开始时间 + 1天                        │
│  计算 newDate = 当前结束时间 ± months                │
│       ↓                                             │
│  if (newDate ≤ minDate):                             │
│       自动修正为minDate + 弹窗提示                    │
│  else:                                              │
│       更新结束时间为newDate                           │
│                                                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  点击"提交起草"                                      │
│       ↓                                             │
│  先调用 validateAndFixEndTime()                      │
│  再校验一次结束 > 开始                               │
│  通过后才写入数据库                                   │
│                                                     │
└─────────────────────────────────────────────────────┘
```

## 六、异常处理设计

| 异常场景 | 处理方式 | 用户提示 |
|----------|----------|----------|
| 数据库未启动 | 弹窗询问是否启动start.bat | "未连接到数据库，是否启动？" |
| 数据库启动超时 | 5分钟后停止轮询 | "等待数据库超时，请检查数据库服务" |
| 表不存在 | 自动执行init.sql初始化 | Splash画面显示"正在初始化数据库..." |
| 登录密码错误 | 区分于其他失败场景 | "用户名或密码错误！" |
| 登录但待审核 | 特殊提示 | "您的账号正在等待管理员审核" |
| 登录但被拒绝 | 特殊提示 | "您的账号已被管理员拒绝" |
| 取消自身管理员权限 | 拦截并恢复勾选 | "不能取消自己的管理员权限！" |
| 结束时间早于开始时间 | 自动修正或弹窗提示 | "已自动调整为 xxx" |
| 分配合同时无权限人员 | 列表中不显示 | 列表标签注明"(会签权限)"等 |
| 合同内容无权限查看 | 灰色占位文字 | "[您没有权限查看...]" |

## 七、设计总结

| 设计维度 | 方案选择 | 理由 |
|----------|----------|------|
| 架构模式 | 三层MVC | 经典可靠，适合中小型桌面应用 |
| 权限模型 | RBAC | 灵活可扩展，符合课程要求 |
| GUI框架 | Java Swing | 课程要求，无需额外依赖 |
| 数据库 | Oracle | 课程要求，免费版功能完备 |
| 启动方式 | 一键启动 | 降低使用门槛，提升用户体验 |
| 日期处理 | 多重校验+自动修正 | 保证数据一致性，减少用户操作负担 |
