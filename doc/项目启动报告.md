## 二、项目背景与目标

### 2.1 项目背景

随着企业业务规模的扩大，合同数量日益增多，传统的人工纸质管理模式已无法满足高效、规范的管理需求。合同管理涉及多个部门协作（起草、会签、审批、签订），流程复杂且需要严格的权限控制和审计追踪。

### 2.2 项目目标

本项目旨在开发一套完整的合同管理系统，实现以下核心目标：

1. **合同全生命周期管理**：覆盖从起草到签订的完整流程
2. **角色权限控制**：基于RBAC模型的细粒度权限管理
3. **用户注册审核**：新用户需经管理员审核后方可使用系统
4. **操作日志审计**：记录所有关键操作，支持事后追溯
5. **一键启动部署**：简化运维，降低使用门槛

## 四、技术方案

### 4.1 架构设计

采用经典的三层架构模式：

```
┌─────────────────────────────────────────┐
│              表现层 (View Layer)         │
│   LoginFrame / RegisterFrame / MainFrame │
│   13个功能面板 (panel/*.java)            │
├─────────────────────────────────────────┤
│              业务逻辑层 (Service Layer)   │
│   UserService / ContractService / ...    │
├─────────────────────────────────────────┤
│              数据访问层 (DAO Layer)      │
│   UserDao / ContractDao / ...            │
├─────────────────────────────────────────┤
│              数据库 (Database)           │
│   Oracle 26ai Free (scott/tiger)         │
└─────────────────────────────────────────┘
```

### 4.2 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 表现层 | Java Swing | 课程要求，轻量级桌面GUI |
| 业务逻辑层 | 纯Java Service类 | 无需额外框架，保持简洁 |
| 数据访问层 | JDBC + PreparedStatement | 直接操作Oracle，性能可控 |
| 数据库 | Oracle 26ai Free | 课程要求，免费版功能完备 |
| 构建管理 | Maven | 依赖管理自动化 |

**核心表关系说明：**

- **t_user** ↔ **t_right** ↔ **t_role** : 用户通过权限表关联多个角色
- **t_role** ↔ **t_function** : 角色包含多个功能（逗号分隔存储）

- **t_contract_process** : 合同流程记录，关联合同编号和操作人
- **t_contract_state** : 合同状态变更记录

## 七、风险识别与应对

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|----------|
| Oracle数据库连接问题 | 高 | 高 | 启动时自动检测，提供start.bat一键启动脚本 |
| Swing界面美观度不足 | 中 | 低 | 统一配色方案，使用彩色按钮增强视觉效果 |
| 权限逻辑复杂度高 | 中 | 中 | 采用成熟的RBAC模型，角色-功能映射清晰 |
| 时间处理边界情况 | 中 | 中 | 输入失焦自动校验，加减按钮限制最小值 |
