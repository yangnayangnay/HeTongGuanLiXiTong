## 二、项目背景与目标

### 2.1 项目背景

随着企业业务规模的扩大，合同数量日益增多，传统的人工纸质管理模式已无法满足高效、规范的管理需求。合同管理涉及多个部门协作（起草、会签、审批、签订），流程复杂且需要严格的权限控制和审计追踪。同时，企业对智能化、无纸化办公的需求日益增长，需要引入AI辅助、电子签名等现代化技术手段。

### 2.2 项目目标

本项目旨在开发一套基于B/S架构的合同管理系统，实现以下核心目标：

1. **合同全生命周期管理**：覆盖从起草到签订的完整流程
2. **审批否决退回**：审批否决后退回定稿，保留意见供查看
3. **角色权限控制**：基于RBAC模型的细粒度权限管理，后端API验证
4. **电子签名**：Canvas手写签名，实现无纸化签订
5. **AI智能起草**：基于Ollama本地AI，模板填充模式自动生成合同内容
6. **邮件通知**：关键流程节点自动邮件通知相关人员
7. **流程可视化**：看板展示合同流转状态，统计分析辅助决策
8. **用户注册审核**：新用户需经管理员审核后方可使用系统
9. **操作日志审计**：记录所有关键操作，支持事后追溯

## 四、技术方案

### 4.1 架构设计

采用B/S三层架构模式：

```
┌─────────────────────────────────────────┐
│              浏览器 (Browser)            │
│   Chrome / Firefox / Edge               │
├─────────────────────────────────────────┤
│              表现层 (Thymeleaf)          │
│   login.html / register.html / main.html│
│   18个功能页面 (templates/*.html)        │
├─────────────────────────────────────────┤
│              控制层 (Controller)         │
│   PageController / ApiController         │
├─────────────────────────────────────────┤
│              业务逻辑层 (Service)        │
│   UserService / ContractService / ...    │
│   EmailService / AIAssistantService      │
├─────────────────────────────────────────┤
│              数据访问层 (DAO)            │
│   UserDao / ContractDao / ...            │
├─────────────────────────────────────────┤
│              数据库 (Database)           │
│   Oracle 26ai Free (scott/tiger)         │
└─────────────────────────────────────────┘
```

### 4.2 技术选型

| 层次 | 技术 | 选型理由 |
|------|------|----------|
| 后端框架 | Spring Boot 2.7.18 | 自动配置、内嵌Tomcat、简化部署 |
| 模板引擎 | Thymeleaf | Spring Boot官方推荐，服务端渲染 |
| 前端框架 | Bootstrap 4.6.2 + Font Awesome 5.15.4 | 成熟稳定，响应式布局 |
| 业务逻辑层 | 纯Java Service类 | 保持简洁，Spring管理Bean |
| 数据访问层 | JDBC + PreparedStatement | 直接操作Oracle，性能可控 |
| 数据库 | Oracle 26ai Free | 功能完备，序列支持编号自动生成 |
| AI辅助 | Ollama + qwen2:7b | 本地部署，数据不出本地 |
| 邮件通知 | JavaMail + SMTP | 标准协议，配置灵活 |
| PDF导出 | iText | 成熟的Java PDF生成库 |
| 构建管理 | Maven | 依赖管理自动化 |

### 4.3 数据库设计

采用关系型数据库设计，共 **12张数据表**：

**核心表关系说明：**

- **t_user** ↔ **t_right** ↔ **t_role** : 用户通过权限表关联多个角色
- **t_role** ↔ **t_function** : 角色包含多个功能（逗号分隔存储）
- **t_contract** : 合同主表，关联客户(t_customer)、起草人(t_user)
- **t_contract_process** : 合同流程记录，关联合同编号和操作人
- **t_contract_state** : 合同状态变更记录
- **t_settings** : 系统设置（SMTP/AI/电子签名配置）
- **t_contract_file** : 合同文件（签名图片等，BLOB存储）
