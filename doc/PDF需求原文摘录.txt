一、引言
================================================================================

1.1 编写目的
本文档对"合同管理系统"进行详细的需求分析，明确系统的功能需求、非功能需求和约束条件，
为后续的系统设计和开发提供依据。

1.2 项目背景
企业日常运营中涉及大量合同管理工作，包括合同的起草、多部门会签、管理层审批、正式签订
等环节。传统的手工管理模式存在效率低下、流程不透明、难以追溯等问题。本系统旨在利用信息
技术手段，实现合同管理的规范化、流程化和信息化。

1.3 术语定义
  合同  - 企业与外部单位签署的具有法律效力的文件
  会签  - 合同在定稿前由相关部门/人员共同审阅并签署意见的过程
  定稿  - 根据会签意见修改后确定的最终合同文本
  RBAC  - Role-Based Access Control，基于角色的访问控制
  流程  - 合同从创建到归档所经历的状态变化序列

三、功能需求详述
================================================================================

3.1 用户管理模块

3.1.1 用户注册
  功能描述: 新用户通过注册界面创建账号
  前置条件: 系统正常运行，数据库已连接
  输入:     用户名（唯一）、密码（两次确认）
  输出:     注册成功提示（提示等待审核）/ 失败原因
  业务规则: 用户名不能重复；密码不能为空；注册后状态为"待审核"，
            需管理员审核后才可登录
  异常处理: 用户名已存在时提示更换；两次密码不一致时提示重新输入

3.1.2 用户登录
  功能描述: 已审核通过的用户登录系统
  前置条件: 用户账号存在且状态为"已通过"
  输入:     用户名、密码
  输出:     登录成功进入主界面 / 登录失败提示具体原因
  业务规则: 区分三种失败场景：
            ①用户不存在或密码错误
            ②账号待审核中
            ③账号被管理员拒绝

3.1.3 用户审核（管理员）
  功能描述: 管理员对待审核用户进行通过/拒绝操作
  前置条件: 当前用户为管理员身份
  操作:     在待审核列表中选择用户，点击"通过"或"拒绝"
  业务规则: 通过后用户可正常登录；拒绝后用户无法登录；操作记入日志

3.1.4 安全约束
  - 自保护机制：管理员不能取消自己的管理员角色，防止误操作导致无管理员
  - admin账户保护：内置管理员账户不可删除

3.2 合同管理模块

3.2.1 起草合同 (F01)
  功能描述: 有起草权限的用户创建新的合同
  输入字段: 合同名称（必填）、客户（必选）、开始时间、结束时间、合同内容（必填）
  默认值:   开始时间=当天日期；结束时间=1年后
  时间校验: 结束时间必须晚于开始时间至少1天；手动输入时自动修正；
            快捷按钮调整时限制最小值为开始时间+1天
  快捷调整: 减半年、加半年、减一年、加一年 四个按钮（减号在左，加号在右）
  输出:     起草成功后生成合同编号（格式：HT+YYYYMMDD+序号），合同状态设为"起草"

3.2.2 分配合同 (F06)
  功能描述: 管理员为已起草的合同指定各环节负责人
  前置条件: 存在状态为"起草"的合同
  分配项:   会签人员（多人）、审批人员（多人）、签订人员（多人）
  权限过滤: 会签列表只显示有F02权限的用户；审批列表只显示有F04权限的用户；
            签订列表只显示有F05权限的用户
  业务规则: 三组人员必须全部指定才能提交分配

3.2.3 会签合同 (F02)
  功能描述: 被指定的会签人员对合同进行审阅并填写意见
  前置条件: 当前用户在合同的会签人员列表中，且合同处于"已分配-待会签"状态
  操作:     查看合同内容 → 填写会签意见 → 确认提交
  业务规则: 所有人签完成后合同进入"待定稿"状态

3.2.4 定稿合同 (F03)
  功能描述: 起草人根据会签意见确定最终合同文本
  前置条件: 所有人签人员均已完成会签
  特殊行为: 进入面板时自动选中第一行合同，将原合同内容填充到编辑区供修改参考
  输出:     定稿后的合同进入"待审批"状态

3.2.5 审批合同 (F04)
  功能描述: 审批人对定稿后的合同进行批准或驳回
  前置条件: 当前用户在合同的审批人员列表中
  操作:     选择"通过"或"拒绝"并可填写审批意见
  业务规则: 任一人拒绝则合同终止；所有人通过后进入"待签订"状态

3.2.6 签订合同 (F05)
  功能描述: 签订人完成合同的正式签订
  前置条件: 合同已通过审批
  操作:     确认签订，合同流程结束
  输出:     合同状态变为"签订完成"

3.2.7 合同流程总览
  起草(F01) → 分配(F06) → 会签(F02) → 定稿(F03) → 审批(F04) → 签订(F05)
    [起草]      [已分配]    [会签完成]   [定稿完成]   [审批完成]   [签订完成]

3.3 查询统计模块

3.3.1 合同查询 (F07)
  功能描述: 按合同名称模糊查询合同列表
  查询字段: 合同编号、合同名称、客户、起止时间、起草人、当前状态
  详情展示: 下方详情区展示选中合同的完整信息
  权限控制: 管理员和合同起草人可查看完整合同内容（含合同正文）；
            其他用户只能看到基本信息，合同正文显示
            "[您没有权限查看该合同的详细内容]"灰色提示

3.3.2 流程查询 (F08)
  功能描述: 查看合同的完整流转历史记录
  筛选:     可按合同状态筛选（起草/会签/定稿/审批/签订）
  展示内容: 各环节的操作人、操作时间、操作内容/意见

3.4 基础数据管理模块

3.4.1 客户管理 (F09)
  功能描述: 对客户信息进行增删改查操作
  字段:     客户编号、客户名称、地址、电话、传真、邮编、开户银行、银行账号
  操作:     添加客户、修改客户信息、删除客户（需二次确认）

3.5 系统管理模块（管理员专属）

3.5.1 用户管理 (F10)
  功能描述: 管理系统用户账号
  功能点:   添加用户（可直接设置角色）、编辑用户、删除用户、分配角色
  特殊区域: 上方显示"待审核用户"区域，含通过/拒绝按钮

3.5.2 角色管理 (F11)
  功能描述: 创建和管理角色及其功能权限
  操作:     添加角色（勾选拥有的功能）、编辑角色、删除角色
  存储方式: 角色的功能以逗号分隔的功能编号字符串存储（如 "F01,F03,F07,F08"）

3.5.3 日志管理 (F12)
  功能描述: 查看系统操作日志
  日志来源: 用户注册、用户审核、用户添加/修改/删除、角色分配等关键操作
  展示字段: 序号、操作人、操作内容、操作时间

四、非功能需求
================================================================================

4.1 性能需求
  页面响应时间: < 2秒（本地数据库环境下）
  并发用户数:   单机桌面应用，无需考虑高并发
  数据量支撑:   支持万级合同记录查询

4.2 安全需求
  身份认证: 用户名+密码登录验证
  授权控制: RBAC角色权限，每个功能点独立控制
  操作审计: 关键操作自动记录日志
  自保护:   管理员不能取消自身管理员权限

4.3 易用性需求
  一键启动: 运行App.java即可自动完成所有初始化
  友好提示: 区分不同错误原因给出精准提示（如：待审核/被拒绝/密码错误）
  智能辅助: 日期自动填充、自动校验、快捷调整按钮
